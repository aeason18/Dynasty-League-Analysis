# dynasty-ppg-api

A fitted scikit-learn `Pipeline` that projects a player's next-season PPG
from this season's stats, served with FastAPI and deployed on Modal.

**One piece is left for you to write:** `pipeline_def.py`'s `PositionalScaler`
currently scales every stat against the whole league (a placeholder — see
the TODO comments in that file). Your job is to make it scale each stat
*within its position group* instead, which is the actual point of a
dynasty tool like this (a RB's 14 PPG and a TE's 14 PPG aren't the same
level of performance). Everything else below already works end-to-end with
the placeholder; once you replace it, re-run the fit + redeploy steps at
the bottom and nothing else needs to change.

## Files

| File | Purpose |
|---|---|
| `pipeline_def.py` | The custom transformer (`PositionalScaler`) — **the file you'll finish**. |
| `fit_pipeline.py` | Pulls season-level player stats from Supabase, builds season→next-season training pairs, fits the `Pipeline`, dumps `pipeline.joblib`. |
| `serve.py` | FastAPI app. Loads `pipeline.joblib` once at import; never refits. `GET /`, `GET /info`, `POST /predict`. |
| `pipeline.joblib` | The fitted bundle (`{pipeline, feature_columns, target_column, position_categories, metadata}`). Regenerated by `fit_pipeline.py`, not hand-edited. |
| `schemas.py` | `PredictRequest`/`PredictResponse` Pydantic models, shared by `serve.py` and `docs_app.py` so their schemas can't drift apart. No sklearn/pandas/joblib dependency. |
| `modal_app.py` | Modal deployment entrypoint for the real API — ships `schemas.py` + `serve.py` + `pipeline_def.py` + `pipeline.joblib` into the image, pins scikit-learn to the exact version in `pipeline.joblib`'s metadata, requires Proxy Auth Tokens. |
| `docs_app.py` / `modal_docs_app.py` | A second, public, unauthenticated deployment that serves only `/docs` and `/openapi.json` — no sklearn/pandas/joblib, no `pipeline.joblib`, `/predict` always 403s instead of running the model. Exists purely so a grader can open a docs URL in a browser without needing the Proxy Auth Token headers Modal requires everywhere else. |
| `postman_collection.json` | Health / info / valid-predict / invalid-predict requests with `pm.test` assertions, importable into Postman. |
| `requirements.txt` | Pinned local dev versions (matches what's baked into the Modal image). |

## Model

- **Features** (one row = one player-season): `position`, `season_ppg`, `season_games_played`, `season_total_points`, `years_exp`.
- **Target**: that same player's PPG in the *following* season.
- **Pipeline**: `ColumnTransformer([PositionalScaler, OneHotEncoder(position)])` → `Ridge`.
- Trained on this league's real history (2023–2025 seasons, QB/RB/WR/TE only). With only two season-to-season transitions available, treat predictions as illustrative, not authoritative — `GET /info` reports the holdout MAE/R² honestly.

## Local development

```bash
cd ml_api
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# Fits against live Supabase data (reads ../.env.local for the anon key —
# all the underlying tables/views are public-read, so no service-role key needed).
.venv/bin/python3 fit_pipeline.py

.venv/bin/uvicorn serve:app --reload
# -> http://localhost:8000/docs
```

## Deploying to Modal

```bash
.venv/bin/modal deploy modal_app.py
```

This app requires **Proxy Auth Tokens** (`requires_proxy_auth=True` in
`modal_app.py`) — Modal rejects unauthenticated requests at its edge,
*before* a container spins up, which is the real cost control given a
capped monthly Modal budget. Create a token pair once per workspace:

```bash
modal workspace proxy-tokens create --json
# -> {"Modal-Key": "wk-...", "Modal-Secret": "ws-..."}
```

Every request — from the Vercel frontend, Postman, or curl — must include
both as headers: `Modal-Key: wk-...` and `Modal-Secret: ws-...`. Treat them
as secrets: they're in this repo's `.env.local` (git-ignored) and in
Vercel's Development/Preview env vars (`MODAL_PROXY_KEY`,
`MODAL_PROXY_SECRET`), never committed or exposed to the browser.

Currently deployed at: `https://aeason18--dynasty-ppg-api-fastapi-app.modal.run` (requires Proxy Auth Token headers for every route, including `/docs`).

To deploy the public docs mirror (no auth, `/predict` always 403s — see `docs_app.py`):

```bash
.venv/bin/modal deploy modal_docs_app.py
```

Currently deployed at: `https://aeason18--dynasty-ppg-api-docs-fastapi-docs-app.modal.run` — this is the URL to hand a grader for a clickable `/docs`.

## Frontend

`lib/ml-api/client.ts` calls the deployed API **server-side only** (from
`app/players/[id]/page.tsx`, a Server Component) — the proxy-auth headers
must never reach the browser. It derives the player's most recent season's
stats from the same game log the rest of the page already uses, sends them
to `/predict`, and renders a "Projected Next Season PPG" card. Silently
omits the card (returns `null`, no error) for unsupported positions (K/DEF
aren't in the model), players with no games played this season, or if the
API is unreachable — this is a supplementary projection, not core data.

Requires `ML_API_URL`, `MODAL_PROXY_KEY`, `MODAL_PROXY_SECRET` in the
Next.js environment (see `.env.example`).

## Postman

Import `postman_collection.json`. Set the collection variables `modal_key`
and `modal_secret` (masked as secrets) before running — get them from
`modal workspace proxy-tokens create` if you don't already have them saved.
Run the collection (or each request individually) and screenshot the
results for the assignment: Health (200), Pipeline Info (200), Predict
valid (200), Predict invalid (422).

## Redeploying after you write the real transformer

```bash
.venv/bin/python3 fit_pipeline.py   # regenerates pipeline.joblib with your real logic
.venv/bin/modal deploy modal_app.py # ships the new artifact — same URL, no frontend/Postman changes needed
```
